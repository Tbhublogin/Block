### 2. `lib/domain/logic/board_engine.dart`
Imports only `game_constants.dart`, `board_cell.dart`, `piece.dart` (no Flutter — AI_RULES #2).

**`PlacementResult`** — immutable value type returned by `place()`: `final List<int> fullRows, fullCols;` with manual `==`/`hashCode`/`toString` matching model conventions. Doc comment: for normal pieces these are the lines that became full; for the special piece these are its unconditionally-cleared row/column (AI_RULES #17) — the same fields feed the controller's `clearLines` call.

**`BoardEngine`** — mutable state class:
- `final List<List<BoardCell>> grid` — public read, built in the constructor as `List.generate(gridSize, (_) => List.filled(gridSize, const BoardCell.empty()))` (no literal 8 anywhere).
- `bool canPlace(Piece piece, int row, int col)` — per filled matrix cell compute `boardRow = row + r`, `boardCol = col + c`; return false if either is out of `[0, gridSize)` (handles negative anchors), or if the target cell `isFilled`. True otherwise.
- `PlacementResult place(Piece piece, int row, int col)`:
  - starts with `assert(canPlace(piece, row, col), ...)` (matches the assert style of the models; invalid placement fails loud in debug, controller checks `canPlace` first).
  - fills each filled matrix cell with `BoardCell.filled(piece.landmarkId)`.
  - **Special piece** (`isSpecial`): reports `fullRows = [row]`, `fullCols = [col]` unconditionally, then immediately clears grid row `row` and column `col` (the just-placed cell goes too — it's inside the cleared row), per PRD 5.2 / AI_RULES #17. Done inline; a later `clearLines` call on the same lines is a harmless no-op.
  - **Normal piece**: reports only lines the placement touched that are now entirely filled (a line not touched by the placement cannot have become full) — iterating the affected rows/cols and checking `isFilled` on every cell.
- `void clearLines(List<int> rows, List<int> cols)` — sets every cell of each given row and each given column to `BoardCell.empty()`; idempotent (clearing an already-empty line is a no-op).
- `void reset()` — one-line refill of the grid with empty cells; needed imminently by the lose-then-rewarded-ad reset flow (AI_RULES #19) and trivially in scope for "holds grid state".

### 3. `test/domain/board_engine_test.dart`
`flutter_test`, `group('BoardEngine', ...)` with const `Piece` fixtures built inline (1x1, 1x2, 2x2, 1x8 row, 8x1 column, and `Piece.special`; all sharing one landmarkId). Tests:
1. grid starts 8x8 and entirely empty (and `gridSize == 8` sanity).
2. normal placement: `canPlace` true, cells filled with the piece's landmarkId, empty `fullRows`/`fullCols`.
3. boundary rejection: `canPlace` false and `place()` throws `AssertionError` when the piece hangs off the right/bottom edge or the anchor is negative.
4. overlap rejection: after filling a cell, `canPlace` false for any piece covering it; `place()` throws `AssertionError`.
5. full-row clear: 1x8 piece at row 2 → `fullRows == [2]`, `fullCols` empty; `clearLines([2], [])` empties exactly that row.
6. full-column clear: 8x1 piece at col 3 → `fullCols == [3]`; `clearLines` empties exactly that column, neighbors untouched.
7. a 1x1 placement completing both a row and a column at once (cross) reports both; `clearLines` clears the cross.
8. special piece, lines not full: with scattered (not full) cells in row 4 / column 6, placing `Piece.special` at (4,6) leaves row 4 and column 6 completely empty when `place()` returns, reports `[4]`/`[6]`, and leaves unrelated filled cells (e.g. (0,0)) untouched.
9. special piece, lines fully occupied: same unconditional clear; an unrelated pre-filled full row stays full and is NOT reported — only the special piece's own row/column.
