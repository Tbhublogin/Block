- Board engine implemented (Phase 1, BUILD_PROMPTS 1.2): `domain/logic/board_engine.dart` — pure-Dart mutable `BoardEngine` holding the grid built from the new `gridSize` constant in `core/constants/game_constants.dart` (AI_RULES #5), with `canPlace` (bounds + occupancy), `place` → `PlacementResult` (immutable `fullRows`/`fullCols` value type), `clearLines`, and `reset` (for the rewarded-ad continue flow, AI_RULES #19). Per user decision, the special piece's unconditional row+column clear is applied **inside `place()`** (board state is already cleared when it returns) and its row/column are still reported in the result, so the controller's uniform place → clearLines flow works for all pieces. Unit tests in `test/domain/board_engine_test.dart` (placement, boundary/overlap rejection, row/column/cross clears, special-piece unconditional clear with empty and full lines).
- Piece generator implemented (Phase 1, BUILD_PROMPTS 1.3): `domain/logic/piece_generator.dart` — pure-Dart `PieceGenerator` with an injectable seeded `Random` for deterministic tests. `generateTray()` returns `traySize` (= 3) pieces drawn uniformly **with replacement** from the new const `pieceShapeLibrary` (27 shapes) in `core/constants/piece_shapes.dart` (singles, I variants 2–5 both orientations, 2x2/3x3 squares, 4 small corners, 4 large L rotations, 4 T orientations, S/Z horizontal + vertical), then — with per-tray probability `SPECIAL_PIECE_SPAWN_RATE` (= 1/6, mid-range of PRD 5.2's "every 5–8 refreshes") — swaps one random slot for the const `specialPiece`. Normal tray pieces get deep-copied matrices (the const library lists are never shared); the special piece is rebuilt via `Piece.special`. All generated pieces carry `landmarkId: placeholderLandmarkId` until the civilization content phase assigns real landmarks. Unit tests in `test/domain/piece_generator_test.dart` (tray size, library shape validity/rectangularity/grid fit, tray shapes all known, placeholder landmark, matrix-copy independence, special-piece 1x1 shape, spawn frequency within ±0.04 of the constant over 2000 seeded trays, same-seed determinism).
- Scoring implemented (Phase 1, BUILD_PROMPTS 1.4): `domain/logic/score_calculator.dart` — pure top-level functions `placementScore(piece)` (one `pointsPerCellFilled` per filled cell), `clearBonus(result)` (one `bonusPerLineCleared` per cleared row/column, special piece's reported row/column included), `moveScore(piece, result)` (per-move total), and `hasReachedTarget(score, targetScore)` (PRD 5.3 win comparison). Scoring constants `pointsPerCellFilled = 1` and `bonusPerLineCleared = 10` live in `core/constants/game_constants.dart` per its TODO (AI_RULES #5; exact values were unspecified in the PRD and chosen by user decision 2026-08-30, tunable later).
- Lose condition implemented (Phase 1, BUILD_PROMPTS 1.4): `domain/logic/lose_condition_checker.dart` — pure `isLoseConditionMet(engine, tray)` returning true iff NO tray piece fits at any anchor position (PRD 5.4). Pieces are probed in their stored orientation only — the shape library pre-enumerates all rotations as separate const entries, so no rotation iteration exists by design (documented in the file header). Unit tests in `test/domain/lose_condition_checker_test.dart`, including the required explicit **guaranteed-lose** scenario: full board with four pairwise non-adjacent 1x1 holes blocks every multi-cell piece (plus a negative control where two holes are made adjacent).
- Progress controller implemented (Phase 2, BUILD_PROMPTS 2.2): `application/progress_controller.dart` — Riverpod `Notifier`/`NotifierProvider` (`progressProvider`) holding an immutable `UserProgress` (PRD 11's sketch: `highestUnlockedStageIndexPerCivilization` `Map<String, int>` + `completedCivilizations` `Set<String>`, hand-written ==/hashCode). Persistence: Hive box `progress` (name constant `progressBoxName`, dynamically typed `Box` because it stores both a map and a list entry — typed boxes reject one on `put`), pre-opened in `main()` after `Hive.initFlutter()` and injected via a throw-on-read `progressBoxProvider` (same DI pattern as `sharedPreferencesProvider`). API per BUILD_PROMPTS 2.2: `markStageCompleted(civilizationId, stageIndex)` (unlocks stageIndex+1; at stage 30 → marks the civilization completed and unlocks the next civilization's stage 1; idempotent + monotonic so replays never lower an unlock), `isCivilizationUnlocked(id)`, and `isStageUnlocked(id, index)` (bounds-checked 1..30; civilization 1 unlocked from the start). Every mutation writes to Hive immediately (PRD 12). New constants: `stagesPerCivilization = 30` in `game_constants.dart` (no more inline 30) and `firstCivilizationId = 'civilization_1'` in the controller — the civilization order/ids are placeholder conventions until the Phase 3 catalog defines them (then both become catalog lookups). Unit tests in `test/application/progress_controller_test.dart` using real Hive boxes in per-test temp dirs (Hive has no mock mode).
- Museum controller implemented (Phase 2, BUILD_PROMPTS 2.2): `application/museum_controller.dart` — Riverpod `Notifier`/`NotifierProvider` (`museumProvider`) holding `MuseumState` with `unlockedLandmarkIds` `Set<String>`, persisted in Hive box `museum` via the same throw-on-read `museumBoxProvider` pattern. `unlockLandmark(landmarkId)` is idempotent and returns whether the landmark was newly discovered; called from `GameController.attemptPlacePiece` on every successful placement (fire-and-forget, non-blocking) so the museum fills as a side effect of play — wiring done now per user decision rather than deferring to the screens phase. Unit tests in `test/application/museum_controller_test.dart` (temp-dir Hive boxes); `game_controller_test.dart` extended with a museum group (first placement unlocks, idempotence, rejected placements unlock nothing, multiple landmarkIds accumulate) and its `_container` now overrides `museumBoxProvider`.
- Game controller implemented (Phase 2, BUILD_PROMPTS 2.1): `application/game_controller.dart` — Riverpod `Notifier`/`NotifierProvider` (`gameProvider`, matching the `languageProvider` style rather than the legacy `StateNotifier` API, per user decision 2026-08-30). Immutable `GameState` snapshot (hand-written ==/hashCode/copyWith, codebase convention) holding `stageId` (null while idle), `targetScore`, the mutable `BoardEngine` by reference (every mutation re-emits state so listeners fire while the grid mutates in place), `tray`, `score`, `isLost`, `isWon`. Public API: `startStage(Stage)` (fresh board/score/flags, first tray generated), `attemptPlacePiece(piece, row, col) → bool` (no-op false when idle/ended/piece-not-in-tray/`canPlace` rejects; otherwise place → clearLines → consume piece → refill tray only when empty (PRD 5.2) → `moveScore` added → win check `hasReachedTarget` takes precedence over lose check `isLoseConditionMet`), and `resetBoardKeepingScore()` (PRD 5.4 / AI_RULES #19 ad-continue: engine reset, score + tray kept, `isLost` cleared; no-op when idle or won). Win timing decision: `isWon` flips **immediately** when the target is reached (PRD 5.3 primary wording, user decision 2026-08-30); the stage freezes — further `attemptPlacePiece` calls return false — and `resetBoardKeepingScore` becomes a no-op. A `pieceGeneratorProvider` (overridable `Provider<PieceGenerator>`) injects the generator so tests use fixed/queued trays. The `Stage` model (id, orderIndex 1..30, targetScore) was implemented in `domain/models/stage.dart` (was a stub) since `startStage(Stage)` requires it. Zero Flutter widget imports — riverpod + domain only. Unit tests in `test/application/game_controller_test.dart` (idle no-ops, stage lifecycle, placement/scoring/tray consumption, refill-only-when-empty, line-clear bonus through the controller, immediate win + frozen stage, blocked-board lose scenario with a queued unplaceable refill tray, win-over-lose precedence on the same placement, resetBoardKeepingScore resuming play, post-win reset no-op).
